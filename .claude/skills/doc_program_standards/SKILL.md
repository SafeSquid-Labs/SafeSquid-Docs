# Doc Program Standards

Use this skill when the task is to define or enforce the SafeSquid documentation operating standard.

## Goal

Make SafeSquid documentation the source of truth for product behavior, deployment, operations, and troubleshooting.

## Read first

1. `references/world_class_quality_rubric.md`
2. `references/source_of_truth_policy.md`
3. `references/page_requirements.md`
4. `references/knowledge_integration_rules.md`

Load only the references needed for the current task. Keep this skill lean and treat the reference files as the detailed standard.

## Core rules

- Reject documentation that is merely descriptive, UI-led, or incomplete.
- Prefer technical truth over elegant phrasing.
- Treat deployment safety, validation depth, and troubleshooting depth as first-class quality dimensions.
- State unknowns explicitly. Do not smooth over gaps.
- When current docs, knowledge files, UI observations, and product claims conflict, follow the source hierarchy in `references/source_of_truth_policy.md`.
- Use the world-class rubric as the approval bar, not a style suggestion.

## When improving the documentation system

1. Define the standard before rewriting pages.
2. Update the writer, researcher, validator, and verification skills to enforce the standard.
3. Add specialist skills where the workflow needs deeper expertise.
4. Audit existing docs against the rubric.
5. Rewrite high-priority pages first.

## Deliverables this skill supports

- Documentation quality rubric
- Source-of-truth rules
- Page standards by document type
- Review scorecards
- Skill upgrades and workflow updates
- Gap analyses and rewrite sequencing
