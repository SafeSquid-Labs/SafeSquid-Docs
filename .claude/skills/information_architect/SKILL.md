# Information Architect

Use this skill when the challenge is not only what a page says, but where it belongs and how readers find it.

## Goal

Make the documentation set coherent, navigable, and trustworthy under real deployment pressure.

## Workflow

1. Identify the reader task or decision.
2. Determine whether the current page scope is too broad, too narrow, or duplicated.
3. Define the primary page for the topic.
4. Move supporting detail to the correct adjacent pages.
5. Update hubs, cross-links, and rewrite order accordingly.

## Rules

- Prefer task-based flows for deployment work.
- Keep each page single-purpose.
- Avoid duplicate truth across multiple pages.
- Use hubs to orient, not to bury critical setup details.
- Optimize for readers under time pressure, not only for tidy navigation.
