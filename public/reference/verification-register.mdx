# Verification register

This register shows whether consequential guidance has been checked against a product build. It deliberately does not expose production data, support cases, reviewer identities, or restricted lab artifacts.

<Warning>
  A page marked **Documentation review** has been checked for structure and internal consistency, but its product behavior has not yet been reproduced in the release lab. Do not present it as build-verified.
</Warning>

## Status meanings

| Public status | Meaning | Publication use |
| --- | --- | --- |
| Documentation review | Content and links were reviewed; product behavior is pending | Visible with an explicit warning |
| Lab reproduced | One operator reproduced the procedure on the named build | Eligible for normal-risk publication |
| Independently verified | A second operator reproduced the critical path | Required for high-risk publication |
| Stale | The verification interval expired or a release changed the behavior | Must be reverified or withdrawn |
| Archived | The release is unsupported | Kept outside current operational guidance |

## Evidence record required for each consequential page

1. Page path, commit, content owner, and technical reviewers.
2. Applicable release train and exact build identifier.
3. Lab topology, sanitized inputs, and prerequisite state.
4. Action transcript with timestamps and expected outputs.
5. At least one deliberately reproduced failure where practical.
6. Recovery and rollback observations.
7. Sanitized screenshots, logs, packet evidence, or API responses.
8. Open limitations, unresolved defects, and expiry date.

The restricted evidence ledger stores the underlying artifacts. This public register exposes only status and accountability.

## Release rule

High-risk procedures require **Lab reproduced** plus independent operator approval before the warning can be removed. A product release, configuration change, or expired review returns affected pages to **Documentation review** until they are reverified.
