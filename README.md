# SafeSquid SWG Documentation

Technical documentation for [SafeSquid Secure Web Gateway](https://www.safesquid.com), built with [Mintlify](https://mintlify.com/docs).

**Audience:** security engineers, system administrators, CISOs, and compliance teams.

---

## What this repo is

A documentation-only repository. There is no application code, no backend, and no SDK.
All content lives under `public/`. The Mintlify CLI builds and serves the site locally, and validates content when you run it — there is no CI, so running it is on you before every merge.

**Do not modify** `package.json` or `.do/app.yaml` (the deployment config).
Content changes go in `public/`. Blog posts go in `public/blog/`.

---

## Stack

| Component | Purpose |
|---|---|
| [Mintlify](https://mintlify.com) (`mint` CLI) | Static doc site generator |
| Node.js ≥20.17.0 (LTS) | Runtime for Mintlify CLI |
| npm | Package manager |
| DigitalOcean App Platform | Production deployment — builds and publishes `main` on every push (`.do/app.yaml`) |

**There is no CI.** Nothing runs `npm run validate` automatically, and nothing blocks a merge — run it yourself before opening a PR (see [Validate](#validate-required-before-every-pr) below).

## Install

```sh
# Pin Node 20 LTS (no .nvmrc — set explicitly)
nvm install 20 && nvm use 20
node -v   # expect v20.x

# Install Mintlify CLI and dependencies
npm install
```

---

## Run locally

```sh
npm run dev
# Serves at http://localhost:3000
```

---

## Validate (required before every PR)

```sh
npm run validate
# Must exit 0 before you open a PR. There is no CI — nothing runs this for you and
# nothing blocks a merge if you skip it.
```

Optional link check:

```sh
npm run broken-links
```

All commands run from the repo root. They internally `cd public/` before invoking `mint`.

---

## Deploy

Production deploys automatically via **DigitalOcean App Platform** (`.do/app.yaml`), which runs `npm ci && npm run build` and publishes on every push to `main` — `deploy_on_push: true`. **There is no separate CI step and no staging environment**: a merge to `main` ships to docs.safesquid.com immediately. `npm run validate` and `npm run broken-links` are not run automatically anywhere in this pipeline — run them yourself before merging.

## What NOT to touch

| File / Directory | Why |
|---|---|
| `package.json` | npm scripts and engine constraint — breaks the DigitalOcean build if changed |
| `package-lock.json` | Regenerated by `npm install` — never edit manually |
| `.do/app.yaml` | Deployment config — modify only with an explicit ticket |
| `public/docs.json` | Theme, colors, logo, navbar, footer, integrations — update `navigation` only when adding pages |
| `public/robots.txt` | Search indexing rules |
| `.claude/settings.json` | Agent runtime environment |
| `_old_getting_started_backup/` | Archived content — do not reference or copy from here |

## Contributing

1. All changes via pull request. `npm run validate` must pass before merge.
2. Content files go in `public/<section>/`. File and folder names: `snake_case`, no spaces.
3. New pages must be registered in `public/docs.json` (add to `navigation` only).
4. Every section folder needs a `main.md` navigation hub.
5. **Read `CLAUDE.md` before writing** — it defines authoring standards, voice, six-block structure, CISO-grade bar, formatting rules, and the pre-publication checklist.

## AI agent / Claude Code setup

- **Claude Code:** reads `CLAUDE.md` and `.claude/` directly (canonical files)
- **Gemini, Copilot, all others:** read `AGENTS.md` (symlink → `CLAUDE.md`)
- **Sub-agent definitions:** `.claude/agents/` (doc-researcher, doc-writer, doc-validator, safesquid-sysadmin)
- **To start a documentation task:** invoke the `doc-writer` agent

See `CLAUDE.md` → "Agent Context and Bootstrap" for the full agent workflow.
